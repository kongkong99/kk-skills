# 讲稿驱动的 PPT 生产

核心原则有两条：

1. **时长决定讲稿，讲稿决定页数。** 先问清讲多久，按时长定字数和页数，不凭感觉排页。
2. **模板是讲稿的语法。** 模板有哪些版式、每种放几项，讲稿就用哪些论证方式、分几项。比如分类版式只有 4 栏，讲稿就最多分 4 类。约束在写之前生效，不在写完之后压缩。

## 能力边界

本 Skill 负责流程编排、约束规则、工单结构和 `scripts/build_order_xlsx.py`。其他能力用环境里已有的：

| 需要做的事 | 用什么 |
|---|---|
| 读参考 PPTX、写最终 PPTX、渲染缩略图做目检 | 已有的 PPT / 幻灯片能力（如 pptx 技能、python-pptx） |
| 生成工单、回读工单、校验约束、比对成品 | `scripts/build_order_xlsx.py`（不要手写 xlsx，不要手工校验） |
| 用户要在线表格协作 | 已有的表格能力，**导入同一个 xlsx**，不另建一份 |

## 状态速查

| 阶段 | 产物 | 进入下一步的条件 |
|---|---|---|
| 0 反问需求 | 演讲需求卡 | 时长、页面密度、主题已知；模板已上传或确认用内置版式 |
| 1 读模板 | 版面约束 + 文案简报 + 2–3 个切入角度 | 每种版式都有论证动作、容量和字数上限；**用户选定切入角度** |
| 2 搭骨架 | 骨架表（每页一个论证动作 + 关键句 + 时长） | 通过骨架检查；**用户确认骨架** |
| 3 写讲稿 | 逐页讲稿 + 屏幕文字（页面 JSON） | 每页讲稿时长在 0.5–3 分钟，总时长和目标相差不超过 10% |
| 4 出工单 | `工单.xlsx` | `build` 零错误；**交给用户补素材、确认** |
| 5 出片 | 最终 PPTX | `check --strict` 通过（或用户同意保留占位）；逐页写完；`check --pptx` 零错误 |

## 阶段 0：反问需求

原则：**只问猜不出来、又会改变结果的事；能猜出来的，猜完写在需求卡上让用户改。**

用户一说要做 PPT 或准备演讲，在**同一条消息里**问完下面三件事，不要分几轮问：

1. **主题和模板**（文字问）：讲什么，或最想让听众记住的一个观点；有没有指定模板，有就上传 PPTX，没有就用内置 9 种版式。用户第一句话里已经说了的，不再问。
2. **演讲时长**（选择题，两道题一起弹出）：讲多长时间，不含会后问答。选项：15 分钟 / 30 分钟 / 45 分钟 / 60 分钟以上。
3. **页面密度**（选择题，和上一题一起弹出）：你希望每页 PPT 放多少内容？

| 选项 | 说明 | 每 10 分钟大约几页 |
|---|---|---|
| 一页一句话，翻页就是提词 | 每页只放一句关键句，讲 30–45 秒，最减轻演讲压力 | 15–20 页 |
| 一页一个要点（推荐） | 一个观点加几条理由，讲 1 分钟左右 | 约 10 页 |
| 一页讲完整，会后能单独看 | 内容写全，不听讲也能看懂，适合会后要发给别人的 PPT | 5–7 页 |

不要用「信息密集 / 稀疏」这类词提问，用户容易理解反：页数少的，每页信息反而更密。

**这一阶段不要问**

- 场合受众、收尾动作、讲稿形式：从主题推断，写在需求卡上让用户改。
- 问答和现场演示：时长已经不含问答；哪页要演示，到阶段 2 搭骨架时再定、再扣时间。
- 讲师姓名、头衔、照片、日期、配色、Logo：放到工单的全局设置里，让用户在 Excel 里填。
- 大纲：大纲是阶段 2 的产物。用户主动给了，当作素材用。

**问完后，给一张演讲需求卡**，标明每项的来源，用户看一眼，不对就改（不用等确认，直接进阶段 1）：

| 项 | 内容 | 来源 |
|---|---|---|
| 时长 / 密度 / 页数 | 例：30 分钟，一页一个要点，约 30 页 | 用户选的 |
| 逐字稿字数 | 例：约 6,900 字（按每分钟 230 字） | 计算 |
| 场合受众 | 例：线下沙龙，听众用过 AI，没做过 Skill | 从主题推断 |
| 收尾动作 | 例：扫码加微信 | 从主题推断 |
| 讲稿形式 | 全文逐字稿 | 默认 |
| 主题 / 模板 | 例：用户上传的活动模板，或内置 9 种版式 | 用户给的 |

字数和页数的算法见 `references/script-constraints.md` §2.1。

## 阶段 1：读模板

浏览模板（渲染成图逐页看，不只读文字），产出三样东西：

1. **版面约束**：按 `references/template-constraints.md` §2 给每种版式定字段映射和字数上限；再按 `references/script-constraints.md` §1 标上论证动作和容量，写进 `templates` 的 `content_form`。没有模板就用内置 9 种版式。必填字段按所选页面密度调整：一页一句话时，只需要标题的版式把正文改成可选。
2. **文案约束**：按 `references/copy-brief.md` 从活动名、主办方、插画、配色、示例文字里读出听众、语气、必须兑现的期待、品牌边界、可借用的母题，整理成文案简报。模板信号比需求卡更具体时，更新需求卡并告诉用户。
3. **切入角度**：同一文件 §3，给出 2–3 个角度，每个写清一句话主张、贯穿比喻、开场钩子、结尾收口、和模板的契合，标一个推荐。

交给用户的内容：版面的 3–4 条硬约束（比如「并列最多 3 项」「每页关键句不超过 13 字」）、文案简报，以及切入角度的选项。**请用户选一个角度**，选完进阶段 2。没有模板时，文案约束只来自需求卡，切入角度照样要给。

## 阶段 2：搭骨架

按 `references/script-constraints.md` §2 的七层约束，从时长倒推章节，再从章节排到每一页：

1. 用选定的切入角度定主线：开场钩子、贯穿比喻放在哪几页、结尾怎么收回。
2. 按净讲时长定章节数和每章的时间。章节数不超过目录栏数。
3. 每个论点选一个论证动作，也就是选一种版式；项数不超过该版式的容量。内容多于容量时，按归类、主次分开、拆页、换动作的顺序处理。
4. 给每页写一句关键句，写在标题字数上限以内，语气符合文案简报。
5. 估每页时长，算累计时长。

产出骨架表（格式见同一文件 §3），跑完检查清单，**交给用户确认后再写全文**。用户改骨架只要几分钟，改写完的讲稿要重来。

## 阶段 3：写讲稿

1. 按确认后的骨架逐页写。每页的讲稿只讲这一页的论证动作，字数对应这一页的预计时长。
2. 屏幕文字从讲稿里摘：关键句做标题，项名做卡片或要点。口头说的名字和屏幕上的一字不差。
3. 缺的素材标待补，不编造姓名、数据、截图、二维码。讲师信息一律引用全局设置，不在页面里另写一遍。
4. 写完核对总字数，和字数预算相差不超过 10%。超了就删例子，不删论点；不够就补例子或互动。

字段映射和文案限制见 `references/order-schema.md` §3–§4。

## 阶段 4：出工单

1. 组 JSON：`title`、`templates`、`global`、`pages`，结构见 `references/order-schema.md` §5。每页的讲稿放进 `演讲者备注`。全局设置里没有的讲师信息、日期、配色、Logo，标 todo 留给用户填。
2. 运行：
   ```bash
   python scripts/build_order_xlsx.py build order.json -o <主题>-工单.xlsx
   ```
3. 有错误时脚本不出文件，按提示改 JSON 后重跑。
4. 交付工单，停下等用户。用三五句话说明：一共几页、预计总时长、还有哪些待补，以及怎么改：浅红格直接覆盖，「/」不用管，换模板从下拉选。

一份工单只对应一个工作簿。用户要在线表格时，导入同一个 xlsx。

## 阶段 5：出片

1. 回读并导出：
   ```bash
   python scripts/build_order_xlsx.py check 工单.xlsx --strict --out pages.json
   ```
   退出码 1：用户改出了问题，列给用户，商量着改；退出码 2：还有待补，请用户补齐，用户明确说「先按占位出」才继续。
2. 只以 `pages.json` 为内容依据，一字不改。
3. 逐页生成，写一页验一页：取 `模板ID` 对应的版式，填入屏幕文字，讲稿写进备注栏，保存后回读这一页，确认没有溢出，再做下一页。
4. 全稿校对：
   ```bash
   python scripts/build_order_xlsx.py check 工单.xlsx --pptx 最终.pptx
   ```
   再渲染缩略图逐页目检。发现溢出就回到约束表调小上限，按超容量规则处理这一页，不要偷偷缩字号。
5. 交付 PPTX，一句话说明页数、预计时长和仍保留的占位。

## 硬规则

- 不问时长和页面密度不开工。
- 讲稿的结构服从模板：项数不超过版式容量，没有的论证动作不用。
- 两种占位语义不混用：【待补】（浅红底）= 开工前必须补；「/」= 本页不适用。表里不留空格。
- 模板一律写「中文名（ID）」。
- 一份工单一个工作簿；出片只认工单。
- 不编造任何姓名、数据、截图、二维码。
