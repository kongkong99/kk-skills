# 讲稿与 PPT 相互约束

## 核心范式

**问题。** 常见做法是先写逐字稿，再照着做 PPT。做出来的 PPT 往往不好看，因为文案是被硬塞进模板的：讲稿分了 5 类，模板只有 4 栏；讲稿里一句话 20 个字，标题框只放得下 12 个；最后只能压缩措辞、缩小字号。

**范式。** 写逐字稿之前，先读 PPT 的排版，弄清它的限制。讲稿和 PPT 在同一套约束下一起生成，彼此约束：

| 方向 | 约束什么 | 例 |
|---|---|---|
| **版 → 稿**：排版约束讲稿 | 结构：分几类、几步、几章 | 卡片版式最多 3 栏，讲稿就最多分 3 类 |
| | 句长：每页的关键句 | 标题框放 13 个字，关键句写稿时就写在 13 字以内 |
| | 论证方式：能用哪些讲法 | 模板没有图表页，就不用数据堆论证，改用案例 |
| | 语气：怎么说 | 模板是像素游戏风的开发者沙龙，讲稿就轻松、可以玩梗 |
| **稿 → 版**：讲稿决定 PPT | 页数 | 由讲稿时长和页面密度算出来，不凭感觉排 |
| | 每页用哪种版式 | 这一段讲稿是「并列三点」，就用三卡片 |
| | 屏幕上写什么 | 从讲稿里摘：关键句做标题，项名做卡片，不另写一套 |

**冲突时怎么办。** 讲稿想表达的内容放不进版式时，**先改讲稿的组织方式，不改版式，更不压字**。按这个顺序处理：重新归类 → 主次分开（次要的只口头讲）→ 拆成两页 → 换一种论证方式。都不行，才新增一种版式，并告诉用户。

**结果。** 每页的字在写稿时就已经放得下，出片只是填空和校对，不用再返工删字、调字号。

```
读排版 ──限制──▶ 搭骨架、写讲稿 ──决定──▶ 页数、版式、屏幕文字 ──▶ 出片（填空）
  ▲                                                  │
  └──────── 冲突：改讲稿的组织方式，不压字、不缩字号 ◀──┘
```

## 能力边界

本 Skill 负责流程编排、约束规则、工单结构和 `scripts/build_order_xlsx.py`。其他能力用环境里已有的：

| 需要做的事 | 用什么 |
|---|---|
| 读参考 PPTX、写最终 PPTX、渲染缩略图做目检 | 已有的 PPT / 幻灯片能力（如 pptx 技能、python-pptx） |
| 生成工单、回读工单、校验约束、比对成品 | `scripts/build_order_xlsx.py`（不要手写 xlsx，不要手工校验） |
| 用户要在线表格协作 | 已有的表格能力，**导入同一个 xlsx**，不另建一份 |

## 状态速查

| 阶段 | 在范式里的作用 | 产物 | 进入下一步的条件 |
|---|---|---|---|
| 0 反问需求 | 定时长和密度，也就是讲稿的总量和切法 | 演讲需求卡 | 时长、页面密度、主题已知；模板已上传或确认用内置版式 |
| 1 读排版 | **写稿之前**弄清版式的限制 | 版面约束 + 文案简报 + 2–3 个切入角度 | 每种版式都有论证动作、容量和字数上限；**用户选定切入角度** |
| 2 搭骨架 | 稿和版一起定：每页一个论证动作，对应一种版式 | 骨架表 | 通过骨架检查；**用户确认骨架** |
| 3 按版写稿 | 版 → 稿：在限制里写全文；稿 → 版：从讲稿摘屏幕文字 | 逐页讲稿 + 屏幕文字（页面 JSON） | 每页时长符合密度，总时长和目标相差不超过 10%；没有一页需要压字 |
| 4 出工单 | 稿和版合进同一张表，一页一行 | `工单.xlsx` | `build` 零错误；**交给用户补素材、确认** |
| 5 出片 | 填空和校对 | 最终 PPTX | `check --strict` 通过（或用户同意保留占位）；逐页写完；`check --pptx` 零错误 |

## 阶段 0：反问需求

原则：**只问猜不出来、又会改变结果的事；能猜出来的，猜完写在需求卡上让用户改。**

用户一说要做 PPT 或准备演讲，在**同一条消息里**问完下面三件事，不要分几轮问：

1. **主题和模板**（文字问）：讲什么，或最想让听众记住的一个观点；有没有指定模板，有就上传 PPTX，没有就用内置 9 种版式。用户第一句话里已经说了的，不再问。模板是这个范式的起点，用户有模板时一定请他上传。
2. **演讲时长**（选择题，两道题一起弹出）：讲多长时间，不含会后问答。选项：15 分钟 / 30 分钟 / 45 分钟 / 60 分钟以上。
3. **页面密度**（选择题，和上一题一起弹出）：你希望每页 PPT 放多少内容？

| 选项 | 说明 | 每 10 分钟大约几页 |
|---|---|---|
| 一页一句话，翻页就是提词 | 每页只放一句关键句，讲 30–45 秒，最减轻演讲压力 | 15–20 页 |
| 一页一个要点（推荐） | 一个观点加几条理由，讲 1 分钟左右 | 约 10 页 |
| 一页讲完整，会后能单独看 | 内容写全，不听讲也能看懂，适合会后要发给别人的 PPT | 5–7 页 |

不要用「信息密集 / 稀疏」这类词提问，用户容易理解反：页数少的，每页信息反而更密。

**这一阶段不要问**

- 场合受众、收尾动作、讲稿形式：从主题推断，写在需求卡上让用户改。
- 问答和现场演示：时长已经不含问答；哪页要演示，到阶段 2 搭骨架时再定、再扣时间。
- 讲师姓名、头衔、照片、日期、配色、Logo：放到工单的全局设置里，让用户在 Excel 里填。
- 大纲：大纲是阶段 2 的产物。用户主动给了，当作素材用。

**问完后，给一张演讲需求卡**，标明每项的来源，用户看一眼，不对就改（不用等确认，直接进阶段 1）：

| 项 | 内容 | 来源 |
|---|---|---|
| 时长 / 密度 / 页数 | 例：30 分钟，一页一个要点，约 30 页 | 用户选的 |
| 逐字稿字数 | 例：约 6,900 字（按每分钟 230 字） | 计算 |
| 场合受众 | 例：线下沙龙，听众用过 AI，没做过 Skill | 从主题推断 |
| 收尾动作 | 例：扫码加微信 | 从主题推断 |
| 讲稿形式 | 全文逐字稿 | 默认 |
| 主题 / 模板 | 例：用户上传的活动模板，或内置 9 种版式 | 用户给的 |

字数和页数的算法见 `references/script-constraints.md` §2.1。

## 阶段 1：读排版（写稿之前）

这一步必须在写任何讲稿之前完成。渲染模板，逐页看图，不只读文字，产出三样东西：

1. **版面约束**：按 `references/template-constraints.md` §2 给每种版式定字段映射和字数上限；再按 `references/script-constraints.md` §1，把每种版式翻译成一种论证动作，标上容量（放几项、标题多长），写进 `templates` 的 `content_form`。没有模板就用内置 9 种版式。必填字段按所选页面密度调整：一页一句话时，只需要标题的版式把正文改成可选。
2. **文案约束**：按 `references/copy-brief.md` 从活动名、主办方、插画、配色、示例文字里读出听众、语气、必须兑现的期待、品牌边界、可借用的母题，整理成文案简报。模板信号比需求卡更具体时，更新需求卡并告诉用户。
3. **切入角度**：同一文件 §3，给出 2–3 个角度，每个写清一句话主张、贯穿比喻、开场钩子、结尾收口、和模板的契合，标一个推荐。

交给用户的内容：

- **这套模板会怎样约束讲稿**：3–4 条，用讲稿的语言说，不用版式的语言说。例：「并列最多讲 3 点」「每页的关键句不超过 13 个字」「没有图表页，所以不用数据论证」。
- 文案简报；
- 切入角度的选项。

**请用户选一个角度**，选完进阶段 2。没有模板时，文案约束只来自需求卡，切入角度照样要给。

## 阶段 2：搭骨架

稿和版在这一步一起定。按 `references/script-constraints.md` §2 的七层约束，从时长倒推章节，再从章节排到每一页：

1. 用选定的切入角度定主线：开场钩子、贯穿比喻放在哪几页、结尾怎么收回。
2. 按净讲时长定章节数和每章的时间。章节数不超过目录栏数。
3. 每个论点选一个论证动作，也就是选一种版式；项数不超过该版式的容量。内容多于容量时，按「冲突时怎么办」的顺序处理，在骨架里就解决，不留到写稿时。
4. 给每页写一句关键句，写在标题字数上限以内，语气符合文案简报。
5. 估每页时长，算累计时长。

产出骨架表（格式见同一文件 §3），跑完检查清单，**交给用户确认后再写全文**。用户改骨架只要几分钟，改写完的讲稿要重来。

## 阶段 3：按版写稿

1. **版 → 稿**：按确认后的骨架逐页写。每页的讲稿只讲这一页的论证动作，项数、句长都在这页版式的限制以内；字数对应这一页的预计时长。
2. **稿 → 版**：屏幕文字从讲稿里摘，不另写：关键句做标题，项名做卡片或要点。口头说的名字和屏幕上的一字不差。讲稿里的例子、故事、过渡不上屏。
3. **写到放不下时，回到骨架改结构**，按「冲突时怎么办」处理，同步更新骨架表；不要先写出来，再压缩成能放下的样子。
4. 缺的素材标待补，不编造姓名、数据、截图、二维码。讲师信息一律引用全局设置，不在页面里另写一遍。
5. 写完核对总字数，和字数预算相差不超过 10%。超了就删例子，不删论点；不够就补例子或互动。

字段映射和文案限制见 `references/order-schema.md` §3–§4。

## 阶段 4：出工单

1. 组 JSON：`title`、`templates`、`global`、`pages`，结构见 `references/order-schema.md` §5。每页的讲稿放进 `演讲者备注`，屏幕文字放进对应字段。全局设置里没有的讲师信息、日期、配色、Logo，标 todo 留给用户填。
2. 运行：
   ```bash
   python scripts/build_order_xlsx.py build order.json -o <主题>-工单.xlsx
   ```
3. 脚本报超容量，说明某页在写稿时就违反了约束：回到阶段 3 改这一页的结构，不要在 JSON 里删字凑数。
4. 交付工单，停下等用户。用三五句话说明：一共几页、预计总时长、还有哪些待补，以及怎么改：浅红格直接覆盖，「/」不用管，换模板从下拉选。

一份工单只对应一个工作簿。用户要在线表格时，导入同一个 xlsx。

## 阶段 5：出片

因为每页的字在写稿时就已经放得下，这一步只是填空和校对。

1. 回读并导出：
   ```bash
   python scripts/build_order_xlsx.py check 工单.xlsx --strict --out pages.json
   ```
   退出码 1：用户改出了问题，列给用户，商量着改；退出码 2：还有待补，请用户补齐，用户明确说「先按占位出」才继续。
2. 只以 `pages.json` 为内容依据，一字不改。
3. 逐页生成，写一页验一页：取 `模板ID` 对应的版式，填入屏幕文字，讲稿写进备注栏，保存后回读这一页，确认没有溢出，再做下一页。
4. 全稿校对：
   ```bash
   python scripts/build_order_xlsx.py check 工单.xlsx --pptx 最终.pptx
   ```
   再渲染缩略图逐页目检。发现溢出，说明阶段 1 的字数上限估大了：调小上限，回到阶段 3 改这一页的讲稿结构，不要缩字号。
5. 交付 PPTX，一句话说明页数、预计时长和仍保留的占位。

## 硬规则

- 不读排版不写稿：阶段 1 完成之前，不写任何讲稿。
- 不问时长和页面密度不开工。
- 冲突时改讲稿的组织方式，不压字、不缩字号、不把内容硬塞进放不下的版式。
- 屏幕文字只从讲稿里摘，不另写一套。
- 两种占位语义不混用：【待补】（浅红底）= 开工前必须补；「/」= 本页不适用。表里不留空格。
- 模板一律写「中文名（ID）」。
- 一份工单一个工作簿；出片只认工单。
- 不编造任何姓名、数据、截图、二维码。
