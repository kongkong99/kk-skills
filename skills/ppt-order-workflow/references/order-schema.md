# 工单结构与填写口径

阶段 2 写文案、阶段 3 组 JSON、阶段 4 读工单时查这份文件。脚本 `scripts/build_order_xlsx.py` 按这里的口径校验，两边不一致时以脚本为准，并回头修这份文件。

## 目录

1. 单元格取值的三种语义
2. 工作簿结构（三个 sheet）
3. 页型字段映射
4. 文案限制清单
5. build 的输入 JSON
6. check 的输出 JSON（出片依据）

## 1. 单元格取值的三种语义

| 写法 | 含义 | 表里的样子 | 什么时候用 |
|---|---|---|---|
| 正常文字 | 定稿内容 | 普通 | 内容确定 |
| `/` | 这个字段对本页不适用，不用填 | 灰字 | 版式没有这个字段；或可选字段这页不用 |
| `【待补】缺什么` | 开工前必须补的内容或素材 | 浅红底 `#FDE7E9` | 缺姓名、数据、截图、二维码、照片等用户才有的东西 |
| `【待补】缺什么｜暂定：xxx` | 同上，但先给一版暂定文字 | 浅红底 | 能起草但必须用户确认的内容，如署名行 |

- 浅红底由条件格式实现：单元格以「【待补】」开头就标红。用户用真实内容覆盖整格后，红底自动消失，所以「补齐后去色」不需要人工操作。
- 表里**不允许空单元格**。空格有两种可能的意思，所以脚本一律判错。
- `/` 和【待补】绝不混用。不知道该填什么时用【待补】，不要用 `/` 糊过去。

## 2. 工作簿结构

一份工单对应一个工作簿，固定三个 sheet，名称和列名不能改，脚本按列名回读。

### 2.1 页面工单（一页一行，一行对应一张幻灯片）

| 列 | 写什么 | 规则 |
|---|---|---|
| 页码 | 1、2、3… | 从 1 开始连续，等于成品页序 |
| 页型 | 封面 / 观点页… | 必须与所选模板的页型一致；有下拉 |
| 推荐模板 | `中文名（ID）`，如 `三卡片（three-card）` | 中文名给人核对，ID 给系统选版式；有下拉，下拉源是模板目录 A 列 |
| 主标题 / 副标题 | 标题文字 | 受字数上限约束 |
| 正文块1–3 | 正文；**一行 = 一个并列点**，用换行分隔 | 每块受字数上限约束；全页行数之和受并列点数上限约束 |
| 配图描述 | 这张图画的是什么，让人和 AI 都能核对图是否放对 | 写了描述，配图URL文件就不能是 `/` |
| 配图URL文件 | 文件名或链接 | 没有真实素材就标【待补】，不找替代图 |
| 演讲者备注 | 本页讲稿（逐字稿或讲述要点），出片时写进备注栏 | 所有版式都可选，但走讲稿流程时每页都写；不受字数上限约束 |
| 待补项 | 本页缺什么的汇总，如 `配图URL文件：讲师照片` | 脚本自动生成；没有待补写 `/` |
| 制作备注 | 给出片环节的说明，如拆页原因、配色例外 | 没有写 `/` |

冻结首行和前 3 列（页码、页型、推荐模板），数据区下方预留 50 行，样式和下拉在预留行照样生效。

### 2.2 模板目录（模板约束表）

每种版式一行。字段口径见 `template-constraints.md`。最后两列是公式：

- `本套使用次数` = `COUNTIF(页面工单!C:C, 本行下拉值)`，用户在表里换模板后自动更新；
- `占比` = 使用次数 ÷ 总页数。

目录下方有「本套总页数」「已用版式数 x / y」两个汇总格，用来看覆盖面和节奏。用了 0 次的版式整行变灰。

### 2.3 全局设置

| 设置项 | 默认用途 |
|---|---|
| 讲师姓名 | 封面署名、讲师介绍页 |
| 讲师头衔 | 讲师介绍页副标题 |
| 活动名称 | 封面署名行、结束页 |
| 活动日期 | 封面署名行 |
| 品牌主色 / 品牌辅色 | HEX 色值，出片时的主色与辅色 |
| 字体 | 中文标题和正文字体 |
| Logo文件 | 封面与结束页角标 |

缺省的项自动标【待补】；确定不需要的写 `/`。可以追加自定义项（如「主办方」）。全局设置下方是给用户看的填写说明，回读时遇到空行即停止，不会把说明当成设置。

## 3. 页型字段映射（默认 9 种版式）

必 = 必填，可 = 可选（不用填 `/`），— = 不适用（必须 `/`）。演讲者备注对所有版式都是「可」。

| 版式 | 主标题 | 副标题 | 正文块1 | 正文块2 | 正文块3 | 配图描述 | 配图URL文件 |
|---|---|---|---|---|---|---|---|
| 封面（cover） | 必 | 可 | 必（署名行） | — | — | 可 | 可 |
| 讲师介绍（speaker） | 必（姓名） | 必（头衔） | 必（履历） | — | — | 必 | 必（照片） |
| 章节过渡（section） | 必 | 可 | — | — | — | — | — |
| 双栏文字（two-col） | 必 | 可 | 必（左栏） | 必（右栏） | — | — | — |
| 三卡片（three-card） | 必 | 可 | 必 | 必 | 必 | — | — |
| 观点页（viewpoint） | 必（观点） | 可 | 必（论据） | — | — | 可 | 可 |
| 金句页（quote） | 必（金句） | 可（出处） | — | — | — | — | — |
| 图文页（img-text） | 必 | 可 | 必（说明） | — | — | 必 | 必 |
| 结束页（ending） | 必（行动号召） | 可 | 可（联系方式/领取说明） | — | — | 可 | 可（二维码） |

解析了参考模板时，以模板目录里的「必填字段 / 可选字段」为准，这张表只代表默认骨架。

## 4. 文案限制清单

写每一页前先对照这一页的约束，写完不应该再需要删减。

1. **字数**：按去掉空白后的字符数计，中文、英文字母、数字、标点各算 1。正文块的上限是**每一块**的总字数。
2. **并列点**：正文块里一行算一个并列点，全页所有正文块的行数之和 ≤ 并列点数上限；用到的正文块数 ≤ 槽位数。
3. **三卡片**的每块只写一行，格式为「卡片标题：一句说明」，出片时按第一个冒号拆成卡片标题和说明。
4. **超容量处理**：内容天然多于版式容量（如 4–5 个并列点放三卡片）时，**拆页或换版式**，并在制作备注写明原因。禁止合并条目、删关键词、缩写成电报体来硬塞。
5. **不编造**：姓名、头衔、数据、客户名、截图、照片、二维码、链接，用户没给就标【待补】。暂定文字只能是格式示意（如「讲师｜活动｜日期」），不能是看起来像真的假信息。
6. **页型与内容形态匹配**：观点页放判断加理由，不放流程；金句页只放一句话；图文页必须有真实的图。
7. **节奏**：同一版式不连续使用；金句页、三卡片是节奏点，每种不超过总页数的 15%（至少允许 1 次）；封面在第 1 页、结束页在最后一页，各用一次。同页型反复出现是一致性需要，单调感来自节奏，不要为了「看起来丰富」去换不合适的版式。

## 5. build 的输入 JSON

```json
{
  "title": "工单名称",
  "templates": [ ...可省略，省略则使用默认 9 种版式... ],
  "global": {
    "讲师姓名": "张三",
    "讲师头衔": {"todo": "讲师头衔（≤24 字）"},
    "Logo文件": "/"
  },
  "pages": [
    {"页码": 1, "模板ID": "cover",
     "主标题": "……",
     "正文块1": {"todo": "讲师姓名、活动日期", "draft": "讲师｜活动｜日期"},
     "演讲者备注": "开场先问……"},
    {"页码": 7, "模板ID": "three-card", "主标题": "……",
     "正文块1": "卡片标题：一句说明", "正文块2": "……", "正文块3": "……",
     "制作备注": "原 4 个并列点，拆为本页 + 第 8 页"}
  ]
}
```

- 页面对象的键就是页面工单的列名。`页型` 可省略，按模板自动填。`推荐模板` 可代替 `模板ID`（写成 `中文名（ID）`）。
- 字段取值：字符串 / `"/"` / `{"todo": "缺什么", "draft": "可选的暂定文字"}`。
- **不适用和可选不用的字段可以不写**，脚本自动填 `/`。**必填字段不写会报错**，必须给内容或 todo。这样每个缺口都是有意识标出来的。
- `待补项` 列不用写，脚本按 todo 汇总。
- `templates` 每项的键：`id`、`name`、`page_type`、`looks_like`、`use_when`、`required`、`optional`、`max_points`、`limits`（`{"主标题": 18, "副标题": 28, "正文块": 30}`）、`content_form`、`rhythm`（开场/转场/主体/节奏点/收尾）、`source`（来源页或版式名）。完整口径见 `template-constraints.md`。

## 6. check 的输出 JSON（出片依据）

`check 工单.xlsx --out pages.json` 导出：

```json
{
  "global": {"讲师姓名": "张三", "Logo文件": null},
  "pages": [
    {"页码": 1, "页型": "封面", "模板ID": "cover", "模板": "封面（cover）",
     "模板来源": "模板第 1 页", "主标题": "……", "副标题": null, "正文块1": "……",
     "配图URL文件": {"todo": "真实二维码图片"}, "制作备注": null}
  ]
}
```

`null` = 工单里的 `/`；`{"todo": …}` = 用户同意保留占位的待补项。阶段 4 只读这个文件，不读对话里的旧稿。

## 7. 校验规则速查

**错误（build 不出文件，check 退出码 1）**

- 页码不是从 1 开始连续递增
- 模板 ID 不在模板目录里（新版式必须先登记）
- 页型与模板页型不符
- 空单元格
- 不适用字段有内容
- 必填字段为 `/`，或在 JSON 里缺失
- 任一字段超字数上限（暂定文字也算）
- 正文并列点总数超上限
- 写了配图描述，配图URL文件却是 `/`
- 版式定义本身不自洽（字段名错、正文块不连续、缺字数上限等）

**提醒（不阻断）**

- 连续两页同一版式
- 节奏点版式用得过多
- 第 1 页不是封面、最后一页不是结束页，或封面/结束页出现多次
- 推荐模板的中文名与目录里该 ID 的中文名不一致
- 有配图文件却没有配图描述

**待补（check --strict 退出码 2）**：仍有【待补】格，包括全局设置。

**成品比对（check --pptx）**：页数不一致、某页找不到工单主标题（页序错位或措辞被改写）、空白页 → 错误；仍有【待补】占位、空占位符、演讲者备注未写入 → 提醒。
