# 从模板读出文案约束和切入角度

阶段 1 浏览参考模板时读这份文件。版面约束管「屏幕上能放多少」，这份文件管「讲稿该怎么说、从哪说起」。

模板不只是版式。活动名、主办方、插画、配色、示例文字，都在告诉你这场演讲是给谁的、该用什么语气、什么比喻能和画面呼应。先读这些信号，再定文案约束，最后给出 2–3 个切入角度让用户选。

## 目录

1. 要读的信号
2. 文案约束（文案简报）
3. 切入角度
4. 与需求卡冲突时

---

## 1. 要读的信号

逐页浏览模板（渲染成图看，不只读文字），记下这些：

| 信号 | 去哪看 | 能推出什么 |
|---|---|---|
| 活动名、副标题、场次 | 主视觉、封面、页眉 | 活动定位（公开课、沙龙、工作坊、发布会）、城市和场次 |
| 主办方、联办方 Logo | 页眉、页脚、主视觉 | 听众来自哪个社区；哪些品牌要尊重，哪些话题要避开（比如竞品） |
| 插画、吉祥物、视觉风格 | 主视觉、结束页 | 可以借用的比喻和母题（像素游戏、城市地标、人和机器人击掌） |
| 配色、字体 | 全部页面 | 语气轻重：活泼的字体和撞色适合轻松口语，深色商务风适合克制正式 |
| 示例占位文字 | 各版式里的「这里是标题文案」 | 标题的写法、是否允许英文副标题、头衔格式（如「机构 / 职位」） |
| 关键词 | 活动名、副标题 | 听众期待：「实战」「落地」「工作坊」意味着要能照着做的步骤，「峰会」「洞察」意味着要观点和趋势 |

## 2. 文案约束（文案简报）

把信号整理成一张文案简报，每条都写清它来自哪个信号：

| 项 | 写什么 | 例 |
|---|---|---|
| 听众 | 是谁、懂多少、为什么来 | 开发者和架构师，来自技术社区，想把 AI 用进企业业务 |
| 语气 | 口语还是正式、能不能玩梗 | 轻松，可以用极客梗和游戏梗，不说官话，不灌鸡汤 |
| 必须兑现的期待 | 活动关键词对应的承诺 | 「实战工作坊」→ 至少一段能现场跟着做的步骤 |
| 品牌边界 | 主办方要尊重的、要避开的 | 联办方的产品可以讲具体功能，但不硬广；不提竞品 |
| 可借用的母题 | 能和画面呼应的比喻 | 企鹅和机器人击掌 → 人和 AI 搭档 |
| 格式惯例 | 标题、头衔、引用的写法 | 金句页可以中英双语；头衔写成「机构 / 职位」 |
| 本地化 | 城市、场次带来的破冰素材 | 长沙站 → 开场可以用本地梗 |

文案简报约束的是整份讲稿，和版面约束一起交给阶段 2。

## 3. 切入角度

切入角度 = 用什么主线把主题讲出来。同一个主题，换一个角度，开场、比喻、结构、结尾都会跟着变。

**怎么生成**：把「主题」和「模板信号」两两组合，挑出 2–3 个最站得住的。常见的来源有三种：
- **借画面**：用模板的插画或视觉风格做贯穿全场的比喻；
- **借活动定位**：按活动关键词调整主题的重心（比如个人经验 → 团队落地）；
- **借听众痛点**：从听众最常遇到的一个场景切进去。

**每个角度写清 5 件事**：
1. 一句话主张：用这个角度，整场在说什么；
2. 贯穿比喻：开场提出，中间反复用，结尾收回；
3. 开场钩子：第一分钟说什么；
4. 结尾收口：怎么收到需求卡上的收尾动作；
5. 和模板的契合：用哪些版式最多，需要什么素材。

**怎么选**：给出 2–3 个角度，标一个推荐，说明理由，请用户选。这是阶段 1 唯一要用户拍板的事，选完直接进阶段 2。用户都不满意，就按他的意见改一版。

## 4. 与需求卡冲突时

阶段 0 的需求卡里有一些是推断出来的（场合受众、收尾动作）。模板给出的信号更具体时，以模板为准，更新需求卡，并告诉用户改了什么、为什么。

例：需求卡推断听众是「用过 AI 的初学者」，但模板写着「开发者沙龙」「企业落地实战工作坊」，联办方是架构师技术同盟。那就把听众改成「开发者和架构师，想把 AI 用进企业」，讲稿相应少讲概念、多讲落地。
