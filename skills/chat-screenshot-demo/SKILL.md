# 模拟聊天案例生成器

用户要求聊天记录图片时，先将对话写入 UTF-8 JSON，再调用本技能内的 `scripts/generate.py`，并将生成的 PNG 展示给用户。按用户要求，画面不显示“模拟案例”“教学演示”等额外标识；在交付说明中如实说明虚构对话为示意，不声称它是真实聊天记录。用户未指定时，顶部 `title` 使用自然的虚构联系人昵称，而不是“客户咨询”等场景名称。

1. 按用户要求编写对话；未指定的称呼、时间和头像可合理设置，不必逐项追问。用户已提供逐字内容时，准确保留；需要生成案例时，按场景组织自然、简洁的对话。联系人名称使用自然的虚构昵称。头像参考用户提供的微信头像素材保持多样性，可有风景、动物、人物远景、插画等，不限制题材或统一风格，不默认做大脸；按聊天窗口比例缩小。优先使用用户提供后经过处理的头像，或使用虚构头像；不能冒用可识别的他人照片。用户提供的群聊信息截图可能含姓名和其他个人信息，裁取时只取头像区域，不能把姓名、聊天文字等带入；对整个头像区域做马赛克或模糊，而不是只打码人脸，并检查导出画面。原图不嵌入成品；即使处理后，形状、背景或独特标识仍可能被辨认，不能保证匿名。合适头像不可用时明确说明，不能把文字占位说成已满足要求。
2. 将 JSON 存到用户工作区，使用下面的数据结构。头像和图片消息路径须指向本地已有文件；图片消息的 `image` 是文件路径，不是网络 URL；相对路径以输入 JSON 文件所在目录为基准。
3. 运行 `python3 "<本技能目录>/scripts/generate.py" --input "<输入 JSON 路径>" --output "<输出 PNG 路径>"`。需要 Python 3、Pillow 和支持中文的字体；生成器会优先使用当前 Python，并在 Pillow 不可用时尝试 Codex 自带的 Python。两者都不可用时按报错提示处理。输出文件必须以 `.png` 结尾。检查输出确实生成；如可查看图片，应检查文字是否截断或重叠。
4. 向用户展示 PNG，并提供可继续修改的 JSON 路径。若用户要求修改，编辑 JSON 后重新运行，不必重写整个工具。

```json
{
  "title": "小林",
  "status_time": "9:41",
  "participants": {
    "left": {"name": "客户", "color": "#D3C6B8"},
    "right": {"name": "顾问", "color": "#A9CBB8"}
  },
  "messages": [
    {"side": "left", "text": "你好，我想了解一下课程。", "time": "今天 10:30"},
    {"side": "right", "text": "你好！你主要希望解决什么问题呢？"}
  ]
}
```

`participants.left` 和 `participants.right` 可选，支持 `name`、本地 `avatar` 路径、`avatar_template` 和 `color`。技能内置 10 个已整块像素化的头像模板，编号 1–10；没有显式头像时左侧按案例稳定选择，同一联系人及滚动视频保持同一头像。同批多个案例默认依次设置 `participants.left.avatar_template` 为 1–10，超过 10 个再循环，避免连续案例使用相同头像；群聊可在消息的 `sender.avatar_template` 设置编号。显式 `avatar` 优先于 `avatar_template`。不指定模板时按案例内容稳定计算；可设置顶层 `avatar_case_key`（例如案例 ID），在文案修改后继续保持原头像。自动计算可能发生哈希碰撞，需要保证不重复时显式分配编号。群聊未显式指定头像时，按成员昵称稳定区分前 10 位，同名成员须显式编号；右侧默认行为保持不变。头像在成图中为 100×100 像素。生成器会在内存中裁成显示区域，再对整个区域像素化后绘制；JSON 顶层可选 `avatar_pixel_blocks`（3–10 的整数，默认 5，数越小打码越强，不能关闭全图打码）。如果 `avatar` 指向包含群成员头像和姓名的整张截图，务必在同一 participant 或单条消息的 `sender` 内设置 `avatar_crop: [左, 上, 右, 下]`，以 EXIF 方向修正后的原图绝对像素指定只含头像、不含姓名的裁剪框，坐标为整数、左上包含且右下不包含；检查框的内容与像素化效果。普通消息的 `side` 为 `left` 或 `right`，`text` 为正文；`time` 可选，会在该消息前添加时间分隔。`side: system` 用于居中的提示。图片消息使用 `type: image` 和本地 `image` 路径，视频封面使用 `type: video` 和 `image` 路径，普通文字消息可用 `quote` 添加引用。`type: card` 以 `text` 和可选 `detail` 生成聊天记录卡片。

群聊设置 `group: true`，可选 `announcement`；左侧消息显示昵称，单条消息可通过 `sender` 对象覆盖参与者的 `name`、`avatar` 或 `color`。完整实例见本技能目录的 `examples/demo.json`。未指定左侧头像时自动从内置 10 个模板中选择；右侧未指定头像时仍为昵称文字占位。图片和视频封面需使用用户提供或获准使用的素材。

转账卡片使用 `{"side":"left","type":"transfer","amount":"92.00","status":"已收款"}`；`status` 只能填写“已收款”或“已被接收”，默认为“已被接收”，金额最多两位小数。可参考 `examples/demo.json`。这是教学模拟图，不代表真实付款或收款。

图片宽度为 1260 像素，短对话默认至少 2736 像素高（约 9:19.5 的手机竖屏），底部保留输入栏，不要缩成近方形；长对话按内容生成纵向长图。单张图最多 100 条消息；以生成器当前支持的功能为准，不能生成的功能要明确说明。

## 滚动视频

用户要求模拟滑动聊天记录时，在同一份 JSON 中提供超过一屏的对话，并运行 `python3 "<本技能目录>/scripts/animate.py" --input "<输入 JSON>" --output "<输出 MP4>"`。默认约 16 秒、1260×2736、60 fps，参数 `--duration`、`--fps`（24、30 或 60）、`--width` 可调整；例如 `--fps 30 --width 720` 可加速预览。需要可运行的 FFmpeg，可通过 `FFMPEG` 环境变量指定。模板根据参考录屏实现多段滑动、减速、短暂停顿和回滑；固定标题与输入栏，视频无音轨。生成后抽查视频的滚动、固定栏和画面完整性，不添加用户不需要的模拟标识；向用户展示 MP4，并保留可编辑的 JSON。参考 `examples/scroll.json`。
